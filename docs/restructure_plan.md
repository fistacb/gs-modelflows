# gs-modeling 見直し計画（2026-11-26）

## A. 構成（5 段階）

| 段階 | 目的 | 出力 |
| :--- | :--- | :--- |
| 1. 入力の前処理 | 背景透過・画像の正規化・3D 化適性・原画の目印の計測 | 透過済みの正面図、目印の JSON |
| 2. 生成 | ComfyUI（TripoSplat）で 2〜4 シードを生成 → PLY を正規化 → 比較して選ぶ | 採用 PLY と選んだ理由 |
| 3. 全体の整理 | 姿勢 → 大きな面・輪郭 → 静止ディテール・掃除。最後にリグを付けやすい姿勢かを確認する | 整理済みの素体 PLY |
| 4. 顔の調整（必須） | 顔ディテールの整理 → 動く目 → 動く口 | 本体 PLY と顔の状態パーツ |
| 5. リグ付け（必須） | ボーン・ウェイト・v1 パッケージ・首振り ±18°・短い確認動画 | v1 パッケージ |

- 削除: Option A（頭部移植。実制作で破綻したため）
- 用途オプション: 小物の追加 / 演技ムービー・納品用の動画 / 下流スキル（gs-to-sprite、gs-to-mesh）への受け渡し
- キャラ条件別の追加手順（references に 1 ファイル）: 顔のアクセサリー / 長い髪・マント / 背面資料あり / 細密キャラ（262k 点）

## B. 進め方

1. 棚卸し（済。結果は下の「棚卸しの要点」）
2. 段階ごとの取り決め: 入出力のファイル名・フォルダ構成・合否の基準（verify_gate の数値とセルフチェックの関係）
3. SKILL.md の書き直し: 本体には流れと原則だけを書き、詳細は references/stage1〜5.md に分ける
4. 道具の整備: 共通化の候補を標準スクリプトにする
5. 検証: 新しい手順で 1 体を通し、速さと品質を今と比べる

## C. 高速化（品質を落とさない）

- 減らすもの:
  - 途中の画像報告。画像を送るのは、完了・3 回で止まったとき・方針の判断が要るときだけ
  - 調整中の全角度レンダー。直した部位と、それが見える角度だけ撮る
  - 数値で分かることを目視で確かめること。数値の検査が先、レンダーはその後
  - 全工程のやり直し。段階の出力を固定し、影響を受ける段階から再開する
  - キャラ専用スクリプトの書き直し
- 減らさないもの:
  - 各段階の確定時の固定撮影セット（真横 90° を含む）
  - verify_gate、セルフチェック、独立 QA
  - 確定時の本番解像度と同じレンダラー
  - 前後比較での同じカメラ
  - 3 回で止めるルール
- 消費トークンを減らす 4 つの方法（導入済み。詳細は references/efficiency.md）:
  1. 1 回の試行 = 1 回のスクリプト呼び出し（scripts/check_candidate.py: 数値 → 通ったときだけレンダー → 1 行の要約。詳しい値は JSON に残す）
  2. 画像をメインの会話に入れない（目視はサブエージェントに任せて文字で受け取る。自分で見るのは判断の場面だけ、scripts/make_sheet.py の縮小シート 1 枚で）
  3. 段階ごとに区切る（確定ファイル＋qa/stage_<n>_handoff.md で引き継ぎ、段階ごとにサブエージェントへ渡せる形にする）
  4. 数値の検査を先に（数値で落ちた候補はレンダーしない。目視で見つかった問題のうち測れるものは verify_gate に足す。第 1 弾: 真横の体幹の傾き ±8°・靴底の傾き ±3°）
- 検証: 所要時間・レンダー回数と、QA 通過・やり直し回数、消費トークン（キャッシュ読み込み量・呼び出し回数・会話に読み込んだ画像の枚数）を今と比べる。品質が下がった変更は元に戻す

## B-2. 段階ごとの取り決め（下書き）

### フォルダ構成

```
<work>/
  character_config.json
  01_input/   front_raw.png, front_rgba.png, landmarks.json
  02_gen/     seeds/seed_<n>.ply, seeds_sheet.png, chosen.ply, choice.md
  03_body/    body.ply（確定）, work/（途中の候補）
  04_face/    head_base.ply, eyes/, mouth/, face_states.json
  05_rig/     v1/（パッケージ）, check.mp4
  qa/         views/<段階>/, attempt_log.md, <段階>_qa.md, gate_<n>.json
```

- 各段階は前の段階の確定ファイルだけを読む。確定ファイルは上書きせず、やり直すときは影響を受ける段階から再開する。
- `work/` の途中候補は確定後に消してよい。

### 段階ごとの入出力と合否

| 段階 | 入力 | 出力（確定） | 数値の検査 | 自分の確認 | 人間の確認 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 原画 | front_rgba.png, landmarks.json | gate0（解像度・透過・顔幅） | 透過漏れ・穴、目印の位置 | 3D 化に向かない原画のときだけ |
| 2 | front_rgba.png | chosen.ply, choice.md | 点数・NaN・高さ 1.0 | シード比較シートで選ぶ | 候補が拮抗したときだけ |
| 3 | chosen.ply, landmarks.json | body.ply | verify_gate 1（縦横比・浮遊点・ヤコビアン・保護範囲の不変・90° の傾き） | セルフチェック Gate 1 | 確定時に画像報告 |
| 4 | body.ply | head_base.ply, eyes/, mouth/ | verify_gate 2（バスト縦横比・浮遊点・前後比較） | セルフチェック Gate 2 | 確定時に画像報告 |
| 5 | 4 の出力 | v1/, check.mp4 | verify_gate 3・4（ボーン内包・左右対称・動画の尺と見切れ）＋首振り ±18° | 動画本体を見る | 完了時に動画で報告 |

- 順序はどの段階も「数値の検査 → 自分の確認 → 独立 QA」。数値で落ちたら目視に進まない。
- 数値が通っても目視で落ちることはある（snowdrop の 90° の傾き）。目視で落ちた問題のうち数値にできるものは verify_gate に足す（例: 90° の体幹の傾き角）。

### 調整中の最小の撮影

| 段階 | 調整中に撮るもの | 確定時に撮るもの |
| :--- | :--- | :--- |

| 2 | シード比較シート 1 枚 | 同じ |

## 棚卸しの要点

- 標準で足りなかった所:
  - 前処理: ML 切り抜き、輪郭線で閉じた穴の穴埋め
  - 段階 3 全般: 標準スクリプトがない
  - step4b: 前髪が消える、静的まつげが二重線になる、まぶたがはみ出す
  - procedural_mouth: 口の位置・幅を手で直している
  - レンダラー: Blender と Spark が混在している
- 共通化の候補（元にする実装）:
  - 1: 切り抜きと穴埋め（rerun_sakura の input_mask、fill_holes）、原画の目印の計測（face_contour_measure）
  - 2: シード比較シート（build_sakura の compare_seeds）、固定カメラの撮影（rerun_sakura の review。広げた共分散を使う）
  - 3: 汎用変形器とヤコビアンの折り返し検査（shape_sakura の transform_gaussians）、姿勢・傾き補正（correct_sakura）、原画の行への縦合わせ（align_sakura_design）、離れた塊の除去、背面のふくらみの作り直し（rebuild_hood_back）、厚い曲面パーツ（make_leaf）、前後比較シート
  - 4: 顔の面の当てはめ（face_surface）、顔の肌の作り直し（face_skin）、旧まつげの除去・まつげ帯・まぶたの切り取り（lash）、表情の書き出し（build_sakura_face の expression）、目の飛び出しの断面検査（audit_sakura_eyes）、頬の掃除
  - 5: 専用スクリプトなし
- 何度もやり直した問題:
  1. 姿勢の前後の傾き（段階 3。snowdrop では 17° の後ろ傾きを見逃した）
  2. 背面のふくらみ・後ろ髪の帯（段階 3）
  3. 花びら・肩・襟の面（段階 3）
  4. 静的まつげの二重線、60° で浮く目の縁（段階 4）
  5. 顔の平たさ・あご下（段階 3・4）

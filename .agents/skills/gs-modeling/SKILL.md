# 3DGS Character Asset & Rig Pipeline (Modular Flow)

## スキルの目的
**デザイン画に準拠した綺麗な 3D ガウススプラット（`.ply`）を作ること**、および **アニメーションで使いやすいリグ・動的ドールアイ（瞬き・ウインク・視線移動）・動的プロシージャル口（開閉・あいうえおリップシンク）の仕組みを組み込むこと** が本スキルの目的である。
ガウススプラット生成および各修正の節目では、個別の数値や一部パーツだけでなく、**デザイン画の印象・バランス・クリーンさを総合的に満たせているか（全体確認）** を必ず確認する。

---

## 核心ルール（最小限の必須事項）
1. **Python 処理・Blender は確認レンダリング専用**: 座標変換・切り出し・マージ・変形は Python（NumPy/SciPy）で行い、Blender GUI 統合は行わない。
2. **ディスク空き容量の確保**: 作業前に作業ボリュームの空き容量を確認し、10 GB 未満の場合は十分な空きがある別ボリュームへ作業ディレクトリと `TEMP`/`TMP` を逃がす。
3. **UTF-8（BOM なし）の徹底**: Node.js（`capture.mjs`）が読む JSON は必ず BOM なし UTF-8 で書き出す（Windows PowerShell 5.1 等の BOM 付与に注意）。
4. **データ駆動（固定値の禁止）**: 顔の輪郭・目の位置・ボーン位置・本数などを特定キャラの固定値で直書きせず、3DGS 点群の実測値（断面重心・ランドマーク・相対比率）から算出する。
5. **デザイン画との総合一致確認 ＆ プロシージャル優先の整理原則（必須）**:
   - **余計な再生成・継ぎ接ぎ結合をしない**: TripoSplat 等のモデル生成が細部（目・口・襟・柄・小物等）で粗くなるのは前提とする。粗い箇所を別モデル再生成の継ぎ接ぎで誤魔化さず、**3DGS の編集しやすさを活かして元デザイン画（`front_raw.png`）を基準にプロシージャルに直す**（汚れた古いスプラットを中途半端に残して上塗りせず、対象領域を更地化してから単一 3D 曲面へ高密度マイクロスプラットで再構成する）。
   - **数値は異常検知の最低ライン**: `verify_gate.py` の数値（縦横比・浮遊点率・ボーン偏差など）は破綻や見切れを弾くための安全網であり、数値を合わせるために顔の輪郭や立体バランスを壊す非線形ワープを行ってはならない。
   - **全体確認を抜かさない**: 局所調整の過程で一時的に局所最適へ寄るのは許容しつつも、節目ごとに必ず **元デザイン画と全体像（アップ＋斜め／全身）を同一基準で確認** し、「印象・バランス・アップ時のクリーンさ（まだら・二重・ズレなし）」を総合的に満たしてから動画化・提出へ進む。
6. **調整ループの軽量化 ＆ QA の実行タイミング分離（過剰パッチ防止）**:
   - **調整中（Inner Loop）**: 修正のたびに `verify_gate.py` や独立サブエージェント QA・全アングル出力を毎回回さない。デザイン画 1:1 比較プレビューを目視して素早く仕上げる。
   - **確定時（Milestone Check）**: 仕上がった段階で **1 回だけ** `verify_gate.py`（数値・幾何の機械チェック）と、元デザイン画を併記した独立ブラインド QA を実行する。
   - **独立 QA の原則**: 修正経緯を伏せたブラインド状態で、「元デザイン画と 1:1 で並べてユーザーに見せられる品質か（PASS / FAIL）」と**デザイン画にないゴミ・破綻・致命傷のみ**を簡潔に判定する（※些末な指摘を無理やり絞り出す運用は禁止）。
   - **早期停止（最大 3 回）**: 同じ問題が 3 回で収束しない場合は即座に停止し、現状画像を添えてユーザーへ方針確認する。

## 検証ゲート一覧（Layer 1 機械チェック ＋ Layer 2 デザイン画突合）

各ゲートは **`verify_gate.py` v3.0（Layer 1：数値・幾何・比率・浮遊点・オーバーレイ自動生成）** と **元デザイン画付き独立ブラインド QA（Layer 2：美観・掃除漏れ・破綻判定）** の 2 層で完結させる。

| ゲート | Layer 1: 機械チェック（`verify_gate.py` v3.0） | Layer 2: 視覚・デザイン画突合（独立ブラインド QA） |
| :--- | :--- | :--- |
| **Gate 0** 入力 | 解像度・背景透過・顔幅（`gate0_check_input.py`） | 透過漏れ・明色穴あき・ポーズ適性 |
| **Gate 1** 素体 | 点数 / NaN / 高さ `1.0` / **3D 浮遊点（kNN外れ値）** / **1:1 デザイン画縦横比（伸び・潰れ `<= ±10%`）＋ 50/50 オーバーレイ生成** | 1:1 オーバーレイで頭身・輪郭の伸び/潰れ・肩/襟/背面の浮遊ゴミ・破綻を確認 |
| **Gate 2** 目・顔 | **バスト 1:1 デザイン画縦横比（伸び・潰れチェック）＋ 50/50 オーバーレイ** / 3D 浮遊点 / Before-After 回帰シート（デザイン画バスト自動クロップ） | 顔全体・鼻筋・頬・目の下・顔面アクセサリー（眼鏡等）の枠と内側・首元の掃除漏れゼロ、二重まぶた・白目漏れ・**首振り±18°時の目/口ズレゼロ** |
| **Gate 3** リグ | 全ボーン内包（はみ出し `<= 0.004`）・断面重心乖離・左右対称性・X-ray 3面図自動レンダリング | 関節位置の自然さ・ポーズ破綻チェック |
| **Gate 4** 動画 | 先行 Gate 2/3 通過確認・動作尺（`>= 2.0s/動作`）・上端見切れ全フレーム走査・**Frame 0 vs デザイン画 1:1 オーバーレイ** | **`.mp4` 本体を直接確認**（揺れ・チラつき・まぶた破綻・掃除残しゼロ） |

## コア工程（最小必須フロー）

キャラクター固有設定は [character_config.template.json](./resources/character_config.template.json) を作業フォルダへコピーして使用する。環境パスと `v1/` パッケージ仕様は [package_v1_spec.md](./references/package_v1_spec.md) を参照。

### Gate 0: 入力確認
- **単一画像前提（ローカル TripoSplat）**: ローカル TripoSplat は単一画像専用のため、4 面シートよりも **高解像度な単体正面図 1 枚** を優先して用意する。
- **3D 化適性チェック（横顔・首元の破綻防止）**:
  - **塗り・輪郭線**: 太い黒アウトライン（特に顎・耳・首周り）は 3D 推論時に横顔の黒壁・えぐれになりやすいため、**黒線の弱い 3D アニメ／フィギュア調の立体陰影**を推奨。
  - **表情**: 2D 記号的な全開の歯見せ笑顔は横顔が平たく破綻しやすいため、**閉じた口または穏やかな微笑み**を推奨。
  - **ポーズ**: リグ・腕動かしを予定する場合は **75°〜85° のリラックス T ポーズ、かつ手のひらを正面（カメラ側）に向けた状態** が望ましい（指の分離と前腕ツイストの安定性が高い）。
- [step0_prep_image.py](./scripts/step0_prep_image.py) で背景透過し、外周・閉空間の背景残留や明色パーツの穴あきがないか目視確認する。
- [gate0_check_input.py](./scripts/gate0_check_input.py) で解像度・ポーズを確認する。
  - 全身正面図単体で顔解像度が不足する場合（目安: 顔幅 `< 120 px`）は、高解像度な単体図へ差し替えるか、**Option A（高精細バスト頭部移植）** の採用を検討する。

### Gate 1: 3DGS 素体生成・正規化
1. ComfyUI（`--base-directory` 配下に `custom_nodes`, `models`, `user`, `input`, `output`, `temp` を作成）を起動し、[step0_generate_ply.py](./scripts/step0_generate_ply.py) で `.ply` を生成する（標準 `65,536` 点、細密・高頭身キャラは必要に応じて `262,144` 点）。
2. [step0_inspect_ply.py](./scripts/step0_inspect_ply.py) → [step1_normalize.py](./scripts/step1_normalize.py) で正規化（直立・高さ `1.0`・`nan_or_inf == 0`）。真横図（`90°`）で **靴底が水平（前傾・後傾なし）** であることを確認する（長いポニーテールやマントがある場合は靴底平面基準で直立を確認）。
3. 形状・顔立ち・破綻を **元デザイン画との 1:1 並列比較画像（全身＋バスト全体）** で確認し、デザイン画にない浮遊塊・首元/肩/襟のゴミ・黒点・接続段差をすべて掃除する（必要ならシード変更や Option A を適用）。
4. 確定時に `verify_gate.py --gate 1` ＋ 元デザイン画付き独立ブラインド QA を 1 回実行し、一致確認を通過してから次へ進む。

### Gate 2: 動的ドールアイ・独立まぶたシェル ＆ 動的プロシージャル口（必須工程）
- **すべてのキャラクターで必ず実行する**（静止目・静止口のままスキップしない）。瞬き・ウインク・視線移動が可能な動的ドールアイ／まぶたシェルに加え、**口の開閉・あいうえおリップシンク**が可能な動的プロシージャル口を組み込む。
- スクリプト:
  - 目・まぶた: [step2_fit_skeleton.py](./scripts/step2_fit_skeleton.py) → [step3_carve_sockets.py](./scripts/step3_carve_sockets.py) → [step5b_polish_splats.py](./scripts/step5b_polish_splats.py) → [step4_generate_eyeballs.py](./scripts/step4_generate_eyeballs.py) → [step4b_eyelid_shell_test.py](./scripts/step4b_eyelid_shell_test.py)
  - 口・リップシンク: [procedural_mouth.py](./scripts/procedural_mouth.py)（`detect_mouth_landmarks` → `carve_mouth_pocket` → `build_procedural_mouth` / `MOUTH_PRESETS`: `closed`, `smile`, `A`, `I`, `U`, `E`, `O`）
- **相対スケール原則**: 眼球半径・眼窩くり抜き・まぶたシェル幅/高さ・上まつ毛ラインおよび口の開口幅/高さは、眼間距離 `D_eye`・顔幅 `W_face`・顔面曲率 `y_surf(dx, dz)` の実測値からデータ駆動で算出し、斜め視点でのはみ出しや二重口を防ぐ。
- **単一アーモンド開口曲線 ＆ 高密度マイクロスプラット**: 眼窩くり抜き・上まつ毛・可動まぶた肌カーテン（まつ毛ラインより上のみ生成し下方滲みを防ぐ）・動的オクルージョンを **同一のパラメトリック曲線** で統一し、二重まぶた化を構造的に防止する。
- **プロシージャル口構造**: 元のぼやけた口ライン・影周辺を肌色で中和し、開口内側のみ小さくくり抜いておくことで、ベース頭部 `.ply` を GPU 上で静的に保持したまま、閉口時は隙間ゼロの繊細なアニメ口線、開口時は奥まった3D口腔・舌と上唇のみのテーパー輪郭線（下唇は枠線なし＋淡い影のみ）を動的に描画する。首振り時のズレ・浮きを防ぐため、口パーツの変形は `head` 100%剛体追従ではなく **口周辺のあご肌スプラットの DQS ウェイト平均（`w_mouth_anchor`）** で追従させる。
- **顔面アクセサリー（眼鏡等）の保護**: 目元にフレーム（眼鏡・装飾等）がある場合は、3D 深度分離＋金属/固有色保護でフレームを守りつつ、フレーム内側のレンズ空間や頬・鼻筋の残留汚れを確実に除去し、まぶた・眼球の外側端がフレーム外へはみ出ない幅に収める。
- **3D Look-At 輻輳（焦点合わせ）**: 視線制御には [harmonic_dqs.py](./scripts/harmonic_dqs.py) の `look_at_eye_rot` を用いてカメラ距離への両眼輻輳を行う。
- **頭蓋骨の剛体化 ＆ 首振り検証（必須）**: `compute_harmonic_skin_weights` により顎より上の頭蓋骨全体（顔・目・口・髪・帽子・顔面アクセサリー）を `head = 1.0` の剛体に固定し、動画生成前に **首振り ±18° の拡大チェック** で目の輪郭線・眼球・口が顔面からズレないことを確認する。
- **デザイン画 1:1 一致確認 ＆ 多角度奥行き確認（必須）**: 動画生成前に、元デザイン画と 1:1 並列した **バスト全体比較＋目元・口元拡大比較（開眼・半目・閉眼・口閉/あ/い/う/お）** に加え、**`0° / ±35° / +60°` の 4 アングル顔アップ** で眼球の奥行き（目頭のめり込み・目尻の飛び出しゼロ）・下まぶたの段差ゼロ・閉眼まぶたと頬肌の色一致・首/襟/アクセサリー周りの掃除漏れゼロを確認する。
- 確定時に `verify_gate.py --gate 2` ＋ 元デザイン画付き独立ブラインド QA を 1 回実行する。

## 選択式オプション（用途・キャラに応じて選択・強制しない）

以下は **用途に応じて組み合わせる選択肢**。

### Option A: 高精細バストによる「頭部丸ごと」移植（高頭身キャラ向け）
- 全身 3DGS では顔が潰れる 6〜8 頭身キャラで、高精細バスト画像が用意できる場合に選択する。
- **重要原則**:
  - **「顔前面だけ」を薄く切り出して低解像度ボディに貼り付けてはならない**（頬の継ぎ目・耳の斑点・首元の色ムラが必ず発生し、パッチ地獄になる）。
  - バスト用 3DGS は全身用の `step1_normalize.py`（重心ピッチ補正がバスト形状で誤作動する）を通さず、**直交回転のみで直立**させる。
  - **帽子・髪・耳・顔・首を丸ごと 1 ピース**として抽出し、接続面は **服の襟の内側だけ** に隠してボディへ接続する。
  - バスト画像は下端を円弧状に切り抜いたり白いギザ縁を残したりせず、クリーンな単色背景（または透過）で用意する。後ろにハルシネーション（尻尾等）が出るシードは避け、別シードでクリーンなバストを選ぶ。

### Option C: 汎用リグ構築 ＆ `v1/` パッケージ凍結（Gate 3 — ポーズ・アニメーションが必要な場合）
- [step7_build_v1_package.py](./scripts/step7_build_v1_package.py) および [harmonic_dqs.py](./scripts/harmonic_dqs.py)（3D kNN 調和ラプラシアン＋DQS＋前腕ツイスト＋動的スプラット補間）でリグと `v1/` パッケージを構築する。
- 調整中は軽量なポーズ確認で収束させ、確定時に `verify_gate.py --gate 3`（全ボーン内包・断面重心乖離・左右対称性・X-ray 3面 [render_rig_preview_blender.py](./scripts/render_rig_preview_blender.py)）＋ 独立ブラインド QA を 1 回実行する。

### Option D: 検証動画 ＆ 演技ムービー（Gate 4 — 動画確認・納品が必要な場合）
- **Spark GPU `SplatSkinning` (`anim` モード) を標準採用する（毎フレームのフルボディ PLY 書き出し禁止）**:
  - `spark_demo/capture.mjs anim <dest> <anim.json>` を使用し、ベース全身 `.ply` と [harmonic_dqs.py](./scripts/harmonic_dqs.py) の `pack_spark_skin_weights` で生成したスキンウェイト（`body_skin.bin`）を **初回 1 回だけ GPU へロード** し、フレームごとに `fk_to_spark_bones` のボーン姿勢配列のみを渡して GPU DQS 変形する（160〜192 フレームを 10〜15 秒で一括描画可能）。
  - 表情パート（瞬き・視線・口パク）のみ軽量の動的パーツ PLY（目・まぶた・口のみ、数百 KB）を `extraPly` で差し替え、全身モーションパートは静止状態の目・まぶた・口 PLY 1 枚を `extraTransforms` で `head` ボーンへ剛体追従させる。
- 標準一括検証動画が必要な場合は [render_standard_qa_video.py](./scripts/render_standard_qa_video.py)（または同構成の `anim` スクリプト）で生成する（1 動作 `>= 2.0` 秒、画面端クリッピング `== 0`）。
- 提出前に `verify_gate.py --gate 4 --video <mp4> --num-segments <N> --min-seg-sec 2.0 --out-dir <qa_dir>` を実行し、独立ブラインド QA では静止画だけでなく **`.mp4` 本体を直接確認** してからユーザーへ提出する。

### Option E: プロップ／装備品の別生成 ＆ ボーン剛体アタッチ（横・背面・手持ちアイテム向け）
- リュック・腰ポーチ・鞘・羽・手持ち武器など、キャラ正面図から見えない／手と癒着すると困る立体アイテムを追加したい場合に選択する。
- **手順**:
  1. キャラ本体はアイテムなしの素体 T ポーズのみで 3DGS 生成・リグ化する。
  2. アイテム単体の正面図（1 枚）から TripoSplat で個別に `.ply` を生成・正規化する（65,536 点で十分）。
  3. Python スクリプトでアイテム `.ply` のスケール・位置・回転を合わせ、親ボーン（`chest` / `pelvis` / `hand_R` 等）へ剛体追従アタッチ（静止時は単純 `concatenate`、アニメーション時は親ボーンの変換行列を適用）する。
- ※立体物ではなく「背中のロゴ・柄のみ」を追加したい場合は、背面参考画像から該当エリアの 3DGS スプラットへ背面投影着色で対応する。

# 品質安定のためのチェックリスト

SKILL.md の各ゲートから参照する。独立 QA を「問題を見つける道具」として使わず、自分で見つけられる問題は QA の前に潰しておくための表。

---

## 1. 固定の撮影セット（全ゲート共通）

毎回同じカメラ・同じ尺度で撮る。途中で視点を変えると前後比較ができない。

| 用途 | 視点 | 備考 |
| :--- | :--- | :--- |
| 全身 | `0°`（原画と同尺度）/ `±35°` / `90°` / `180°` | `90°` は靴底・体幹の鉛直線を引く |
| バスト・顔 | `0°` / `±35°` / `+60°` / `90°` | `+60°` は**遠い側の輪郭**の確認用 |
| 継ぎ目 | 修正した部位と隣接部の拡大 | 修正前後を同じ枠で並べる |

- 撮影は作業フォルダーの `qa/views/<段階名>/` に保存し、ファイル名に視点を入れる。
- **レンダラー由来の見え方を先に除外する**: 縞・帯・ちらつき・不自然な細線を見つけたら、修正に入る前に同じ PLY をレンダラーの設定（Spark の拡張共分散描画、別解像度など）を変えて撮り直す。消えるならモデルではなく撮影側の問題。

## 2. 試行ログ（`qa/attempt_log.md`）

同じ問題の言い換えで 3 回上限をすり抜けないよう、問題に ID を振って記録する。

```
| ID | 部位・問題 | 根拠（視点・計測値） | 試行 | 結果 | 採用 PLY |
| P1 | 遠い側のこめかみが薄く、眉が輪郭からはみ出す | +60° 顔 | 1 | 改善なし | - |
| P1 | 同上 | +60° 顔・横断面 | 2 | 改善 | face_v2.ply |
```

- QA の指摘は既存 ID に寄せられるか先に確認する。言い換えでも同じ部位・同じ原因なら同じ ID。
- 同じ ID が 3 回で収束しなければ止めて、最良候補と残る差を添えてユーザーに確認する。

## 3. 変形・再構成のときの必須確認

- **標準の道具**: 変形は `scripts/splat_ops.py` の `transform_gaussians`、候補の検査は `scripts/check_candidate.py`（下の折り返し・保護範囲・過大スプラット・真横の傾きを 1 回で測る。使い方は [efficiency.md](./efficiency.md)）。
- **折り返し検査**: 局所変形のあとは変形のヤコビアン（`det J > 0`）を確認し、折り返しのある候補は採用しない。振幅を下げて再試行するより、制御点の取り方を見直す。
- **保護範囲の不変**: 触っていない部位（靴底・体幹・確定済みの顔など）の座標が変わっていないことを数値で確認する（`check_candidate.py --protect`）。
- **ガウスの向きと広がりも更新する**: 位置だけ動かすと、引き伸ばした部分に縞や隙間が出る。
- **更地化してから作り直すのは可動部品だけ**: 段階 4 で置き換える目・口の範囲の旧スプラット（旧まつ毛・旧虹彩・旧口線・ぼやけた影）は先に除去する（旧部品を残した上塗りは閉眼時の二重線や斜めの浮きになる）。それ以外の部位（フード・衣装・背面など）は更地化・作り直しをせず、色と陰影の補正で直す。
- **色の補正は「見えている点だけ」を選んで行う**: 原画に合わせる色替えは [front_select.py](../scripts/front_select.py) の `front_visibility`（正面から見えている度合い）と `design_lookup`（その点の下の原画の色）で対象点を選ぶ。座標の箱と色のしきい値だけで選ぶと、裏側・内側・隣の部品まで塗れる。**選んだ点は必ず赤く塗ったタイント版を撮り（正面・±90°・背面）、漏れがないことを確かめてから本番を適用する。** `design_lookup` は外接矩形での対応づけなので、細い帯（裾と脚の境目など）ではずれる。ずれが見えたら使わない。
- **原画にない部位は破綻だけ直す**: 背面・側面の推定形状は好みで作り替えない。直すのは、色の破綻（灰色の濁り・白飛びの筋・色むら）と、形の破綻（ゴミ・穴・帯・二重線・はみ出し・突起・板状・不自然なふくらみ）。形の破綻は後回しにせず、生成の点を使った最小限の変形で原因の工程から直す（色で覆うと後から形を直せなくなる）。
- **原画にある部位は形も 1:1**: 目の形・大きさ、口の位置など原画にある部位の形の差は、原画に合わせて直す。
- **ざらつき**: `front_select.denoise_colours`（色の差で重みをつけた近傍平均。部品の境界は残る）を顔・目を除いて弱めにかけ、`colour_noise` の値と、同じ角度の前後比較で確かめる。半透明の針状スプラットが原因なら、そちらは不透明度の低い細長いスプラットの除去で直す。
- **色は隣接リングから取る**: 再構成した肌・衣装の色は、全体平均ではなく、境界のすぐ外側のスプラットから取る。継ぎ目の拡大で色差を確認する。
- **過大スプラットの掃除**: 境界をまたぐ大きなスプラット（近傍点間隔に対して極端に大きいもの）は、顎下・首・襟・髪の境目で淡い帯や色のにじみとして見える。部位の境界付近で大きさの外れ値を抽出し、除去または分割する。
- **孤立成分の掃除**: 小さな孤立成分は対象部位の中だけで除去する（全体一括の除去は細い装飾や髪先を消す）。

## 4. QA 前セルフチェック（独立 QA を呼ぶ前に必ず自分で確認）

各項目を「済 / 未」で書き出し、未が残っているうちは QA を呼ばない。

### Gate 1（段階 3: 素体）
- [ ] 真横で靴底が水平、足首・膝・腰・肩・頭が想定の姿勢に並んでいる（数値の体幹の傾き ±8°・靴底 ±3° は `verify_gate.py --gate 1` が検査する。数値が通っても 90° のレンダーは必ず見る）
- [ ] **原画のランドマーク高さ**（目・顎・肩・腰・裾・足首・髪先など、そのキャラで原画から位置が読める部位）を原画と正面レンダーで実測して一覧にし、並べて見て分かる差がある部位は直すか、直さない理由を記録した
- [ ] 原画で左右非対称な部位（長さ・形が左右で違うもの）が、左右取り違えずに原画どおり
- [ ] `+60°` と `90°` で頭・頬・こめかみ・顎に厚みがあり、遠い側の眉・まつ毛・目尻が顔の輪郭からはみ出していない
- [ ] 顎下・首・襟・肩の境界に、過大スプラットの淡い帯や色のにじみがない
- [ ] 顎の線・髪の外周がぎざぎざしていない
- [ ] 背面・側面で、衣装や後ろ髪が帯状・板状に見えない（推定部分は自然な厚みがある）
- [ ] 明確な浮遊片・孤立点がない
- [ ] 色替えした部位はすべてタイント版で選択の漏れを確認した。原画にない部位は形を変えず、破綻（濁り・筋・ざらつき・ゴミ）がないことだけを確認した

### Gate 2（段階 4: 目・口）
- [ ] 眼球を入れる前の固定の目の縁が、正面と `+60°` で肌から浮いていない
- [ ] 旧まつ毛・旧虹彩・旧口線が除去済み（閉眼・閉口で二重線が出ない）
- [ ] 目のまわり・口のまわりの再構成部分と肌の色がそろっている（継ぎ目拡大で確認）
- [ ] 開眼・半目・閉眼・ウインク・視線左右、口の閉 / あ / い / う / お をすべて撮った
- [ ] `0° / ±35° / +60°` で眼球の目頭のめり込み・目尻の飛び出し・白目漏れがない
- [ ] **全状態 × `0° / ±35° / +60° / ±90°`**（開眼・半目・閉眼・ウインク・視線左右）を 1 枚のシートで見た。調整中に見ていない状態・角度を QA で初めて見る状態にしない
- [ ] まぶたの開口の内側に、眼窩の壁（くり抜いた面の奥の点）が灰色・紫・赤の帯として見えない（`±35°`・`+60°`・視線左右で確認。見えると眼球の縁が白い弧に見える）
- [ ] 眼球の縁（白目の端）が、視線 ±・`+60°` で粒・筋・ぎざぎざにならない（眼球の覆い範囲が「開口＋視線角＋視点角」を超えている）
- [ ] `+60°`・`±90°` で、近い側の眼球・まつ毛が頬・こめかみの輪郭からはみ出さず、髪の上に浮かない
- [ ] 顔の肌（目の下・頬・鼻の横）に、原画にない赤い点・青紫のしみなど色の外れ値がない（ベース由来でも段階 4 で色だけ掃除する）
- [ ] まつ毛の色が原画の色（黒に近いなど）と合っている
- [ ] Gate 1 のセルフチェック項目が Gate 2 の作業で崩れていない

### Gate 3・4（段階 5: リグ・確認動画）
- [ ] 首振り `±18°` の顔拡大で、目・まぶた・口が顔面からずれない（頭蓋は `head = 1.0` の剛体）
- [ ] X 線 3 面図で、肩・肘・手首・股・膝・足首の関節が体の中の自然な位置にあり、左右対称
- [ ] ポーズ 1〜2 枚で、腕の付け根・股・髪やマントに破れ・伸び・巻き込みがない
- [ ] 確認動画は `.mp4` 本体を最初から最後まで見た（揺れ・ちらつき・まぶたの破綻・上端の見切れ・掃除残しがない）
- [ ] Gate 1・2 のセルフチェック項目がリグ付けで崩れていない（Frame 0 を原画と並べて確認）

## 5. 独立ブラインド QA の依頼文（テンプレート）

毎回同じ文で依頼し、判定のぶれを減らす。修正経緯・試行ログ・前回の指摘は渡さない。

```
あなたは 3D キャラクターモデルの品質判定者です。
添付の原画（front_raw.png）と、同じモデルを複数視点で撮ったレンダー画像を見てください。
側面・背面は原画にないため、自然に推定されていれば良しとします。

判定してほしいこと:
1. 原画と 1:1 で並べてユーザーに見せられる品質か（PASS / FAIL）
2. FAIL の場合、その理由になる問題だけを挙げる。各問題について「部位」「視点」「どう見えるか」を 1 行で。
   対象: 原画にないゴミ・浮遊片・二重線・穴・帯状の破綻、原画と明らかに違う比率や長さ、継ぎ目の色差、輪郭のはみ出し。
   些細な好みの差は挙げない。問題がなければ無理に探さない。
3. 原画にない部位（側面・背面・推定した形）は、形の好みでは FAIL にしない。破綻（ゴミ・穴・帯・二重線・はみ出し・板状や不自然なふくらみ・不自然な色の濁りや筋）だけを判定する。原画にある部位は形の差も判定する。

視点: <ここに撮影セットの一覧>
```

- QA の結果は `qa/<gate>_qa.md` に保存し、指摘を試行ログの ID に対応づける。

## 6. QA FAIL のあとの進め方（局所パッチ禁止）

指摘を 1 件ずつ直すと、直した所だけ良くなり原因の工程は残る（局所最適）。FAIL のときは次の順で進める。

1. **原因を点で特定する**: 指摘ごとに、該当部位の点を種類別（ベース・眼球・追加リング・まぶた・口など）に色分けしたタイント版を、指摘と同じ視点で撮る。見えている点がどの工程で作られたかを確かめる。
2. **指摘 → 工程の表を作る**: `qa/attempt_log.md` に「指摘 / 視点 / 原因の点 / 原因工程」を書く。複数の指摘が同じ工程に集まることが多い。
3. **最も上流の工程からやり直す**: 表の中で一番上流の工程から、表の全指摘を満たす条件にして、下流の工程まで通しで作り直す（下流だけ直して上流の原因を残さない）。それまでの局所パッチは工程に取り込むか捨てる。
4. **固定撮影セットとセルフチェックを全部やり直す**: 指摘の視点だけでなく、そのゲートの全状態・全角度を撮り直し、セルフチェックを全項目「済」にしてから QA を 1 回呼ぶ。
5. **回数の数え方**: 1〜4 の 1 周を 1 回とする。同じ ID が 3 周で収束しなければ止めて、表と現状画像を添えてユーザーに確認する。
